## Assumptions

- **Model:** 155M parameters; 6·N FLOPs per training token, plus ~15% for attention/GDN mixing.
- **Training throughput per H100: 150K / 250K / 350K tokens/s.** This is the most uncertain
  input and the biggest cost driver. 250K tok/s is about 27% of H100 dense BF16 peak, typical
  for a d=768 model, where the matmuls are too small to saturate the GPU. Highly tuned GPT-2-small
  speedruns reach more; our GDN layers use fla's chunked kernels rather than FlashAttention.
  **Measure it before booking** (below).
- **Tokens:** pretraining 1.0-1.5T (deliberately below the 4-10T recall-heavy small models use;
  see docs/research/datasets.md); mid-training 50-100B at 8K→64K context (runs at ~60%
  throughput); ablations 50-200B tokens in total.
- **Teacher data:** 200K kept SFT trajectories; 25-50% survive rejection sampling (correct
  answer, NLI-supported citations, teacher fails closed-book). Each trajectory ≈25K input tokens
  summed over turns, 1.5K output. Base case prices are Qwen3-235B-A22B-Instruct-2507 at
  $0.15 / $0.80 per M tokens; the conservative case uses DeepSeek-V3 at $0.27 / $1.10. Prefix-cache
  discounts would lower this; self-hosting the teacher on rented H100s costs about the same.
- **Counterfactual documents:** mostly rule-based entity/number/date swaps on CPU (free). Only an
  LLM-rewritten subset (0.5-2B output tokens) is paid.
- **Contingency:** 20-40% on GPU hours for reruns, debugging and evaluation.

## Ways to cut it

1. **Measure training throughput first:** one rented H100 for an hour (~$3-4) running the
   training step at the real shapes replaces the biggest assumption.
2. **Spot/preemptible capacity** with frequent checkpoints: about $2.15-2.69/h instead of ~$4.
3. **Stop pretraining at ~1T tokens** if mid-training ablations show reading quality has
   saturated. The goal is a reader, not an encyclopedia.
4. **Rule-based counterfactuals** for nearly all of the 15% counterfactual mix.
5. **Prefix-cached / batch API pricing** for teacher trajectories: every turn re-sends the same
   sources, so caching cuts input cost severalfold.
